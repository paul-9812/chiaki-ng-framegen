# chiaki-ng Frame Generation

**PS5 Remote Play on a Mac, with 30 fps games shown at 60 fps.** No gaming PC and no capture
card: the PS5 streams to the Mac over the home network, and the Mac generates the frames in
between.

This is a fork of [chiaki-ng](https://github.com/chiaki-ng/chiaki-ng) that adds real-time
frame generation on Apple silicon, using the frame interpolation built into macOS.

## Why this exists

I wanted to play GTA VI at 60 fps. On the PS5 it runs at 30, and the projects that fix that
by generating the missing frames, [Robz Play](https://github.com/kutsalkiremitci/robz-play)
and [Veyra-NRVideo](https://github.com/Likely7/Veyra-NRVideo), need a Windows PC with a
dedicated graphics card. I don't have a gaming PC. I have a MacBook.

So I took those two projects as inspiration and built my own version for the Mac, on top of
chiaki-ng. The console keeps rendering 30 frames per second, and the Mac draws one new frame
between every two real ones. What reaches the screen is 60.

## What it does

- **30 fps in, 60 fps on screen.** One generated frame between every two real ones, handed
  to the screen every 16.7 ms.
- **1080p.** The full Remote Play picture, not a downscaled copy.
- **One checkbox.** Settings > Video > *Frame Generation (30 to 60 fps)*, on by default.
  Switched off, the app behaves exactly like chiaki-ng.
- **It tells you what it is doing.** With *Show Stream Stats During Gameplay* on, two extra
  rows show real frames per second > frames shown (`30 > 60`) and the time one generated
  frame takes.
- **Everything else is chiaki-ng**: pairing, PSN login, DualSense support, audio, settings.

Frame generation changes what you see, not how the game responds: the console still reads
your controller 30 times per second.

## How it works

```
PS5 ── 1080p stream, 60 fps ──▶ decoder ──▶ frame generation stage ──▶ renderer ──▶ screen
       (a 30 fps game arrives               1. drop the repeated frames
        as every frame twice)               2. generate the frame in between
                                            3. hand a frame on every 16.7 ms
```

1. **Repeated frames are dropped.** A PS5 streams 60 fps even when the game renders 30, so
   every game frame arrives twice. The copy is re-encoded and never quite identical, so the
   stage compares how much each frame changed with how much frames usually change.
2. **The frame in between is generated by macOS.** The engine is VideoToolbox's low-latency
   frame interpolation (`VTLowLatencyFrameInterpolation`, macOS 26+), made by Apple for live
   video on Apple silicon.
3. **1080p goes in three bands.** On macOS 26.2 one interpolation session takes at most
   921,600 pixels (1280x720). A 1080p picture is split into three overlapping 1920x480
   bands, interpolated side by side and stitched with a feathered seam. Systems that accept
   the whole picture get the whole picture.
4. **Frames leave on a clock.** A real frame and the generated one before it are scheduled
   16.7 ms apart, from a thread that macOS wakes on time (an ordinary thread's timers slip
   by several milliseconds on battery).
5. **What cannot be improved passes through**: a game already at 60 fps, 10-bit HDR
   pictures, or a system without the engine.

The code is in [`framegen/`](framegen) (engine, repeated-frame detection, tests) and
[`gui/src/framegen.cpp`](gui/src/framegen.cpp) (the stage). The benchmarks that led to this
design are in [`framegen/bench/`](framegen/bench).

## Where it stands

**In play.** GTA VI on a PS5 Slim, 1080p stream, MacBook Pro M4 on Wi-Fi: the stats overlay
reads `30 > 60`.

**Measured** on a MacBook Pro 14" (M4, 10-core GPU, 16 GB), macOS 26.2, on battery with Low
Power Mode on, which is the slowest state the machine can be in:

| | |
|---|---|
| One generated 1080p frame | about 17 ms (three bands, side by side) |
| One generated 720p frame | 5 to 9 ms (engine benchmark) |
| Time between frames handed to the renderer | 16.7 ms, within 0.2 ms (test with a timed stream) |
| Extra delay before a real frame is shown | about 40 ms at 1080p |

**Known problems**

- **Drops on Wi-Fi.** With the Mac on Wi-Fi there are visible drops, and chiaki-ng's weak
  connection icon comes up when they happen. Lost packets are the likely cause. It has not
  been tried on a network cable yet.
- **Drops in heavy scenes.** Dense city areas with a lot of traffic drop too. The console
  itself falls below 30 fps in heavy scenes
  ([as low as 23 fps on a base PS5](https://www.altchar.com/game-news/gta-vi-dips-as-low-as-23fps-on-base-ps5-in-heavy-action-digital-foundry-finds-aJybE7x7IsZa)),
  so frames stop arriving evenly, and the stage is not tuned for that yet. Part of this may
  be on our side.
- **HUD and minimap.** Static elements over a moving scene can wobble in generated frames.
  There is no protection for them yet.
- **Delay.** A generated frame can only be made once the next real one has arrived, so
  everything is shown a little later than without frame generation.
- **SDR only.** The engine takes 8-bit pictures. An HDR stream is shown as it is, without
  generated frames.
- **macOS only.** Frame generation needs macOS 26 on Apple silicon. On every other system
  this builds and behaves like chiaki-ng.
- **No download yet.** There is no packaged release; you build it from source (below).

## Requirements

| | Minimum | Recommended |
|---|---|---|
| Mac | Apple silicon | M4 or newer. The base M4 is the only chip measured so far; earlier ones are untested. |
| macOS | 26 (Tahoe) | the latest 26.x |
| Power | | plugged in, with Low Power Mode off |
| Console | PS5 or PS4 with Remote Play enabled | PS5 on a network cable |
| Network | Mac and console on the same home network | Mac on a network cable too, or on 5 / 6 GHz Wi-Fi close to the router |
| Stream settings | SDR (H.264 or H.265) | 1080p, 60 fps, H.265 (not HDR). Try 720p if the delay bothers you: a 720p frame is generated in half the time or less. |
| Display | 60 Hz | a TV or monitor in Game mode, over HDMI |
| Controller | anything chiaki-ng supports | DualSense over USB |

To build it you also need the Xcode Command Line Tools (full Xcode is not needed),
[Homebrew](https://brew.sh) and a few GB of disk space for Qt and the other dependencies.

If the Mac cannot keep up, the `frame generation` row in the stats shows it: the time per
generated frame has to stay well under the 33 ms between two frames of a 30 fps game.

## Build and run

```bash
git clone --recurse-submodules https://github.com/paul-9812/chiaki-ng-framegen.git
cd chiaki-ng-framegen

brew install qt@6 ffmpeg pkgconf opus openssl@3 cmake ninja nasm protobuf@29 speexdsp \
             libplacebo python-setuptools json-c miniupnpc libevent molten-vk

scripts/build-macos-framegen.sh
open build/gui/chiaki.app
```

The script configures the build, compiles the app and the frame generation tests, and runs
the tests. `scripts/build-macos-framegen.sh selftest` also opens the app in a self-test mode
that feeds it synthetic 30 fps video and prints what came out, a check that needs no
console:

```
Frame generation self-test: status "generating", 226 frames in, 436 frames out, 29.3 fps in, 60.5 fps out, 16.91 ms per generated frame
```

## Using it

1. On the PS5: Settings > System > Remote Play > Enable Remote Play.
2. Open the app, allow local network access when macOS asks, and register the console:
   click it, choose *PSN Login*, then type the code the PS5 shows under Remote Play >
   Link Device. The chiaki-ng documentation covers this in detail:
   <https://chiaki-ng.github.io/chiaki-ng/>.
3. Settings > Stream, for PS5, column *Local*: *Resolution* 1080p, *FPS* 60, *Codec* H265
   (not H265 HDR).
4. Settings > Video: *Frame Generation (30 to 60 fps)* checked.
5. Settings > Audio/Wifi: *Show Stream Stats During Gameplay* checked, to see `30 > 60`.
6. Start the stream and the game.

## Tests

```bash
cd build && ctest -R framegen --output-on-failure
```

Two suites, both on synthetic video whose motion is known exactly, so they can tell where
every part of a generated frame has to be and when every frame has to leave:

- `framegen-engine`: the generated frame is the exact midpoint, motion is the same from top
  to bottom (no visible seams between bands), and one 1080p frame takes at most 25 ms.
- `framegen-stage`: 30 fps in gives an even 60 fps out, repeated frames of a 60 fps stream
  are dropped, and everything the stage cannot improve passes straight through.

They need macOS 26 or later on Apple silicon.
